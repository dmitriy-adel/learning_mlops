## ТЗ

- Создать сервис, который обрабатывает входящий текст и предоставляет информацию о нём через API-эндпоинты. Сервис должен быть упакован в Docker-контейнер и доступен для запросов с localhost. Функциональные требования:

    - Эндпоинты (ручки):

    1. /count_words (метод: POST): Принимает текст в теле запроса (JSON: {"text": string}). Возвращает JSON с информацией:

    - Количество слов (разделённых пробелами)
    - Пример ответа: {"word_count": 10}

    2. /count_chars (метод: POST): Принимает текст в теле запроса (JSON: {"text": string}). Возвращает JSON с информацией:

    - Количество символов (исключая пробелы).
    - Пример ответа: {"chars_count": 10}.

    3. /reverse (метод: POST): Принимает текст в теле запроса (JSON: {"text": string}). Возвращает JSON с информацией:

    - Полученная строка, чьи символы идут в обратном порядке
    - Пример ответа: {"reversed": reversed_string}.


## Пайплайн запуска апи

1. билд образа: 

    ```bash
    sudo docker build -t remove_after_test -f sample/text_processing_api.dockerfile .
    ```

2. запуск контейнера: 

    ```bash
    sudo docker run remove_after_test -it --port 8089:8089
    ```

## Что понял

1. контекст сборки **НЕ** может смотреть наверх, он смотрит только вниз. НО мы можем двигать директорию. из которой он смотрит при помощи фалаг `-f` в момент билда образа

2. *uvicorn* не вопрсинимает директории, которые имеют такое же название, как внутренние директории Python. условно, если создать директорию code, через uvicorn не получится запустить скрипт из нее, поскольку она пересекается с приватными репо

3. при отсутствии явной проброски портов хост-контейнер, что логично, контейнер не слушает порты хоста
